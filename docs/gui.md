# GUI 使用手册

适用版本：**0.1.0**
本文档属于 **GenerateProjectContext** 项目。GUI 包为 `project_context_gui`，命令为 `project-context-gui`。
`project_context GUI` 是 `project-context` 命令行工具的图形界面包装。它不重写任何业务逻辑，只是把常用参数通过鼠标点选送进原 CLI 执行，并额外提供 `.project_context/` 配置文件的查看与编辑能力。

## 1. 术语

| 术语 | 含义 |
|---|---|
| **项目根** | 你要分析的项目所在的目录 |
| **项目配置** | 项目根下 `.project_context/` 目录里的配置 |
| **工具内置规则** | 工具自带、随分发包提供的基础排除规则 |
| **本次追加** | 你在 GUI 里临时输入的规则，仅本次运行生效 |
| **最终生效规则** | 内置 + 项目 + 本次追加，合并后的结果 |

## 2. 安装与启动

### 2.1 从源码

```bash
pip install -e ".[gui]"
```

这会安装：

- 原 `project_context` 包
- 可选依赖 `PySide6`
- 可选依赖 `tomlkit`（用于格式化，缺省时“格式化”按钮无效果）

### 2.2 启动

```bash
# 方式一：模块入口
python -m project_context_gui

# 方式二：脚本入口（安装后可用）
project-context-gui
```

### 2.3 系统要求

- Python 3.9+
- 有图形界面的桌面环境
- Python 3.9 / 3.10 需额外 `pip install tomli`

## 3. 三步完成主任务

打开 GUI 后，主流程只有三步：

```
打开项目文件夹 → 点「开始生成」 → 点「打开输出文件夹」
```

### 步骤 1：打开项目文件夹

有三种方式：

| 方式 | 说明 |
|---|---|
| 顶栏「📁 打开项目」按钮 | 弹出系统文件选择器 |
| 拖拽文件夹到窗口 | 拖入任意位置即可 |
| 顶栏「最近项目」下拉 | 快速切换之前打开过的项目 |

### 步骤 2：点「开始生成」

默认参数即可直接运行。若输出文件已存在，会弹一次覆盖确认。

### 步骤 3：点「打开输出文件夹」

成功后：

- 弹窗显示耗时与输出路径
- 状态栏右下角的「打开输出文件夹」按钮变为可点击
- 点击后系统文件管理器打开输出文件所在目录

## 5. Tab 1：运行配置

这是核心页面，分六个区块。

### 5.1 项目与输出

| 控件 | 说明 |
|---|---|
| 项目文件夹 | 必填。选完后输出路径自动填为 `<项目>/PROJECT_CONTEXT.md` |
| 输出文件 | 可改成任意 `.md` 路径 |
| 安静模式 | 勾选后 CLI 不打印进度（日志更简洁） |

### 5.2 语言

| 选项 | 说明 |
|---|---|
| 自动检测（默认） | 预扫描项目，按文件后缀与标志文件判断激活哪些语言 |
| 全部语言 | 强制激活所有 9 种内置语言 |
| 手动选择 | 点「+ 添加语言」勾选需要的语言 |
| 检测阈值 | 至少 N 个文件命中才激活该语言，默认 1 |

### 5.3 输出内容（章节开关）

| 开关 | 对应 CLI |
|---|---|
| 包含源码内容 | 取消后等同 `--no-content` |
| 包含 AST 摘要 | 取消后等同 `--no-ast` |
| 包含 Git 历史 | 取消后等同 `--no-git` |
| 关闭时间戳 | 勾选后等同 `--no-timestamp`（用于快照对比） |

### 5.4 过滤降噪（高级，默认折叠）

四个可重复列表：

- 排除文件 glob（`--exclude`）
- 排除目录名（`--exclude-dir`）
- 排除目录 glob（`--exclude-dir-glob`）
- 排除后缀（`--exclude-suffix`）

每个列表支持：

- 输入后回车或点「添加」
- 粘贴多行自动拆分（逗号或换行分隔）
- 自动去重
- 选中后点「删除选中」或按 Delete
- 排除目录名支持「从文件夹选择…」

另有一个「忽略项目配置」复选框，对应 `--no-inherit-defaults`。

### 5.5 限制（高级，默认折叠）

| 控件 | 默认 | 对应 CLI |
|---|---|---|
| 单文件大小上限 | 200 KB | `--max-file-size` |
| 最大 Git 提交数 | 50 | `--max-git-commits` |
| 每提交文件数 | 20 | `--max-files-per-commit` |

### 5.6 命令预览（高级，默认折叠）

只读文本框，实时显示当前所有选项拼成的命令行。可点「复制命令」粘贴到终端。

## 6. Tab 2：配置文件

查看与编辑项目根的 `.project_context/`。

### 6.1 布局

```text
┌────────────────────────┬──────────────────────────────────────┐
│ 配置文件列表            │ TOML 编辑器                          │
│ ● common.toml          │ 1  inherit_defaults = true           │
│   languages/            │ 2                                     │
│     python.toml        │ 3  [filter]                          │
│     go.toml            │ 4  ignore_dirs = ["local_venv"]      │
│                        │                                      │
│ [新建 common.toml]     │                                      │
│ [新建语言配置…]         │                                      │
│ [删除选中]              │                                      │
│                        │ [校验] [格式化] [保存 (Ctrl+S)]       │
└────────────────────────┴──────────────────────────────────────┘
```

### 6.2 操作

| 操作 | 说明 |
|---|---|
| 点击左侧条目 | 加载到右侧编辑器 |
| 编辑后 | 条目出现 `●`，保存按钮启用 |
| 「校验」 | 解析 TOML，失败时红色高亮错误行 |
| 「格式化」 | 用 tomlkit 重新排版（保留注释） |
| 「保存」 | 先校验，失败拒绝保存 |
| 「新建 common.toml」 | 生成含注释的默认模板 |
| 「新建语言配置…」 | 输入语言名生成模板 |
| 「删除选中」 | 二次确认后删除 |

### 6.3 未保存保护

以下场景会弹「是否保存」对话框：

- 切换 Tab 时
- 关闭窗口时
- 切换到另一个配置文件时

## 7. Tab 3：运行日志

CLI 子进程的 stdout + stderr 实时汇聚。

| 控件 | 说明 |
|---|---|
| 级别过滤 | 全部 / INFO / WARN / ERROR |
| 搜索 | 关键字过滤（大小写不敏感） |
| 自动滚动 | 勾选后新增日志自动滚到底 |
| 清空 | 清空当前视图 |
| 导出日志… | 保存为 `.log` / `.txt` |

日志按级别着色：

- ERROR（含 Traceback）→ 红色
- WARN → 黄色
- INFO → 默认色

## 8. 设置

顶栏「⚙ 设置」打开。

### 8.1 通用

| 项 | 说明 |
|---|---|
| 默认输出文件名 | 默认 `PROJECT_CONTEXT.md` |
| Python 解释器 | 留空用当前 GUI 的 Python；可指定其他虚拟环境 |

### 8.2 外观

| 项 | 选项 |
|---|---|
| 主题 | 跟随系统 / 浅色 / 深色 |
| 字体大小 | 8 – 20 pt |

### 8.3 行为

| 项 | 说明 |
|---|---|
| 启动时恢复上次打开的项目 | 默认勾选 |

### 8.4 执行引擎

GUI 支持两种执行方式，可在设置中切换：

| 模式 | 说明 |
|---|---|
| 自动（默认） | 优先使用本机默认方式，另一方式作为回退 |
| Python | `python -m project_context <args>` |
| EXE | `<generate-project-context.exe> <args>` |

**EXE 路径解析顺序：**

1. 设置中显式指定
2. GUI 可执行文件同目录
3. 系统 PATH

**顶栏模式徽章**：显示当前实际使用的引擎（`🐍 Python` / `📦 EXE`）。点击可直接打开设置。

**使用场景**：

- 开发机：Python 模式（源码可改）
- 分发到无 Python 的用户：EXE 模式
- 两者皆有：自动模式

### 8.5 Python 模式准备

Python 模式通过 `python -m project_context <args>` 执行，需要两样东西：

1. **一个可用的 Python 解释器**
2. **一份 `project_context` 模块**（其父目录在子进程 `PYTHONPATH` 中）

#### 源码运行（开发环境）

无需配置。GUI 自动把项目根（`project_context` 的父目录）注入子进程 `PYTHONPATH`。

#### 打包运行

打包后的 GUI 不含 Python 解释器，也不含 `project_context` 源码。需用户手动准备。

**方案 A：放到 GUI EXE 同目录**

```text
D:\tools\gpcg\
├── generate-project-context-gui.exe
├── _internal/                       ← 自动生成
└── project_context/                 ← 用户手动放置
    ├── __init__.py
    ├── __main__.py
    ├── cli.py
    └── configs/
```

GUI 会自动检测到同目录的 `project_context/`。

**方案 B：在设置中指定父目录**

打开「设置」→「执行引擎」→「Python 模块路径」，填入 `project_context` 的**父目录**（不是包目录本身）。

判定方法：打开该目录，应该能看到 `project_context/` 子目录，而不是直接看到 `__init__.py`。

#### 常见问题

**Q：填了路径但状态行显示“这是包目录本身”？**

你填的是 `D:\...\project_context`。请改填它的父目录 `D:\...\`（即去掉末尾的 `project_context`）。

**Q：填了路径但状态行显示“该路径下没有 project_context/”？**

确认该目录下确实存在 `project_context/__init__.py`。

**Q：状态行显示“未找到 project_context”？**

- 未指定路径时，GUI 只会自动查找程序目录
- 把 `project_context/` 复制到 GUI EXE 同目录，或在设置中指定路径

**Q：Python 模式不可用，能做什么？**

- 改用 EXE 模式（需 `generate-project-context.exe`）
- 或在设置中配置 Python 解释器与模块路径

## 10. 常见问题

### Q：为什么输出文件没有第 5 章（Git 历史）？

项目根没有 `.git` 目录，或「包含 Git 历史」复选框未选中。查看运行日志会看到「未发现 .git，Git 历史章节将被跳过。」

### Q：为什么某个目录没被忽略？

1. 切到「运行配置」→ 展开「过滤降噪」→ 看是否已加规则
2. 若规则没显示，可能是该语言的配置未激活（语言自动检测没命中）
3. 打开「命令预览」看参数是否被拼进命令行
4. 点「查看配置加载说明」查看三层配置的实际加载情况

### Q：想只出结构，不要源码内容

取消勾选「包含源码内容」，或直接命令行：

```bash
project-context . --no-content
```

### Q：AI 上下文窗口有限，如何压缩输出？

- 取消勾选「包含源码内容」
- 把「单文件大小上限」改小（如 50 KB）
- 使用「排除文件 glob」过滤大文件

### Q：能修改非 `.project_context/` 下的 TOML 吗？

GUI 只管理 `.project_context/` 下的配置文件。其他 TOML 请用文本编辑器。

### Q：环境没有 Git 会怎样？

自动降级：文档跳过第 5 章，其余正常生成。日志会提示。

### Q：Windows 上输出乱码？

GUI 强制子进程以 UTF-8 读写；输出文件始终以 UTF-8 写入。若终端显示乱码，是终端本身编码问题，与生成的文件无关。

### Q：我在 GUI 加的排除规则和项目里的配置冲突怎么办？

不冲突，会叠加：

- 项目里 `ignore_dirs = ["third_party"]`
- GUI 加 `--exclude-dir build`
- 最终两者都生效

### Q：为什么项目里配置的规则没生效？

1. 点「运行配置」Tab 底部的「查看配置加载说明」，看「② 项目配置」这一层
2. 若显示「未发现 .project_context/」，说明项目根没有该目录
3. 若已发现文件但规则仍不生效，注意区分：
   - `ignore_dirs` 精确匹配目录名
   - `ignore_dir_globs` 支持通配符

### Q：怎样让一条规则永久生效？

1. 打开「配置文件」Tab
2. 编辑 `common.toml` 或对应语言的 toml
3. 保存后写回项目，下次运行自动加载

或者：在过滤面板输入后，点「查看配置加载说明」，在「③ 本次追加」卡片里点「固化到项目配置」。

## 11. 卸载

```bash
pip uninstall project-context
```

用户设置（主题、最近项目等）保存在系统标准位置：

- Windows：注册表 `HKEY_CURRENT_USER\Software\project_context\gui`
- macOS：`~/Library/Preferences/com.project_context.gui.plist`
- Linux：`~/.config/project_context/gui.conf`

如需彻底清理，手动删除上述位置。
